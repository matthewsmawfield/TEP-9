9. Data availability and reproducibility

9.1 Data record

Raw catalogue snapshots are stored under data/raw/; source-specific provenance records include retrieval details and, where recorded, hashes. CODE is an archival snapshot rather than a successful live export. MPC observations and SBDB fit seeds are cached for the independent refits. Spacecraft data include NAIF kernels, PDS Voyager plasma-wave records and the Whiting & Woerner RTG dataset. Acquisition steps may update live sources; preserving the existing snapshot is necessary for reproducing the present numerical record.

The local companion-manuscript inventory and imported-premise roles are recorded in reviews/COMPANION_PREMISES.json and reviews/CORPUS_SCOPE_CORRECTION.md. The observed-data evidence is separate from Monte Carlo, bootstrap, integration and power controls. Unavailable diagnostics must not be treated as zero measurements or successful tests. The repository-wide audit inventories nonfinite fields and flags source/result provenance uncertainty rather than silently converting missing results into favourable evidence.

9.2 Running and auditing the analysis

scripts/run_all.py lists the analysis order and runs each step in a subprocess, stopping on failure. The claims audit runs after its upstream results. Every registered step and source file is included in the review inventory; the review report records which numerical analyses were actually rerun. A successful syntax check or a result newer than its script does not by itself demonstrate numerical or scientific validity.

scripts/audits/audit_tep9_observables.py independently checks frames, angular arithmetic, direct versus reduced dynamical residuals, the equivalent-time counterexample and the era dipole calculation. Focused regression tests exercise the probability contracts, cone-band union, state ordering and optimiser rejection behaviour. These tests use synthetic mathematical controls, clearly separate from empirical evidence. scripts/experimental/conformal_boundary_response.py separately verifies the prescribed planar boundary response; its test profiles are not fitted field solutions.

The publication source is site/components/. Headline quantitative claims bind to exact JSON leaves through site/claims.json and site/claims.js; invalid, missing or nonfinite bound values stop the build. Running npm run build:markdown in site/ builds the HTML and Markdown from this source. The PDF is generated from the built HTML. The older wording is preserved in reviews/pre_review_components/ for comparison and is not part of the current publication.

9.3 Reproducibility limits

Several cross-channel steps read sibling TEP projects rather than self-contained data in this repository. Their availability and source hashes must be recorded; the present paper does not claim a clean-room rerun of those entire external pipelines. Fixed random seeds do not guarantee identical floating-point results across library versions. The review records the active package versions separately from the declared requirements.
